# Final PDF documentation portfolio — instructor section order

Use genuine screenshots, diagrams, date-stamped logs and source/code excerpts; do not invent evidence.

1. **Cover and roster:** Amazing, Group 1, BSCS2A, course/instructor, full names, roles, contacts, individual consented pictures.
2. **Requirements specification:** problem, target user, scope/limits, FR1–FR13 and non-functional requirements with priorities.
3. **UML:** use-case diagram + main use-case descriptions; class diagram matching actual code; sequence diagram of user pressing Play.
4. **Incremental log:** M1–M5 each: goals, done, changed scope, obstacles, next step; note meaningful refactoring and why.
5. **Version control/collaboration:** real Git commit-history screenshot, role matrix, per-person contributions, branch and PR links, meeting notes, merge conflicts (or state none if none).
6. **Testing/bugs:** >=15 actual test cases including negative cases; record expected/actual/pass/fail, defect fixes and retests.
7. **User manual:** install, import, play, sort/search, favorites, keyboard shortcuts, screenshots, troubleshooting.
8. **Deployment guide:** Windows prereqs, publishing, release ZIP layout, second-computer test, limitations.
9. **Presentation slides and each member's reflection:** demo timeline, technical contribution, lessons learned.
Appendix: source code listing, original design PNG/Canva/PSD source, credits and licenses, logo, final screen.

## Demonstration timing (10 minutes)
1m problem/design rationale; 2m UML; 4m working demo (add, save/reopen, playback, Favorites, error); 2m testing/lessons; 1m Git history/roles. All five present and explain their own and teammates' code.
